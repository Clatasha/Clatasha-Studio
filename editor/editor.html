    Plugin API v1
    VERSIONED AND PERMISSION BASED

    A stable path for new Clatasha tools

    Plugins receive a small Clatasha API instead of unrestricted access to the editor. That keeps the canvas, undo history, themes, and project format under Clatasha Studio’s control.

    01

    Manifest

    Every plugin declares its identity, API version, menu label, entry file, and permissions.

    {
  "id": "company.plugin-name",
  "name": "Plugin Name",
  "version": "1.0.0",
  "apiVersion": 1,
  "type": "tool",
  "runtime": "sandbox",
  "entry": "plugin.js",
  "ui": { "html": "plugin.html", "css": "plugin.css" },
  "menuLabel": "Plugin Name",
  "icon": "icon.svg",
  "permissions": ["canvas.addImage"]
}
    02

    Lifecycle

    An installed tool registers inside a restricted sandbox, follows theme changes, and cleans up everything when closed.

    ClatashaPlugin.register({
    mount({ root, api, theme }) {},
    setTheme(theme) {},
    destroy() {}
});
    03

    Plugin API v1

    • await canvas.getDocumentSize()
    • await canvas.getSelectedImage()
    • await canvas.addImageBlob()
    • await storage.get() / set()
    • ui.notify() / close()
    04

    Release scope

    Package the required files at the root of a ZIP archive, then rename it with the .clatasha-plugin extension. Install it from the Plugins menu and review its permissions.

    Local packages are validated, stored on this device, and run without network access. Image Merger and Image Cipher are included as bundled reference implementations.
